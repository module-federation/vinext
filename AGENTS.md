# AGENTS.md

## Pull request titles

PR titles are validated by `.github/workflows/pr.yml` and must follow
[Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<optional scope>): <summary>
```

- Allowed types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
  `build`, `ci`, `chore`, `revert`.
- Keep the summary short, lowercase, and in the imperative mood, e.g.
  `feat: support shared remote components`, `ci: add e2e test`,
  `chore: bump @module-federation/vite`.
- Mark breaking changes with `!`, e.g. `feat!: drop vinext beta support`.
- Squash-merged PRs land on `main` with the PR title (or the commit title for
  single-commit PRs), so give commits the same format.
- Titles starting with `Release ` are reserved for the PR generated by the
  **Release Pull Request** workflow and skip validation. Don't use that prefix
  for anything else.
